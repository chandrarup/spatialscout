# The lab runs after the verdict; uploaded sections are audited and not kept

The investigation's verdict comes from a frozen rule over verified claims (ADR-0001), and its stored model responses are keyed to its prompts and tools. Follow-up work (literature, a protein cross-check, publication figures) therefore runs as a separate **lab** phase on a finished investigation, with its own contracts, events and recording, and never changes the verdict or the investigation's files.

- **Dispatch.** Muse Wonder chooses **sub-agents** from a fixed registry (`literature`, `protein_crosscheck`, `publication_figure`). Choices are validated in code like tool calls; rejected ones are shown with their reason.
- **Concurrency.** Accepted sub-agents run with `asyncio.gather` (CPU work in worker threads). Each start and finish is an event with its real timestamp; the timeline on screen is drawn from them.
- **Literature.** Records come only from Europe PMC, fetched live and stored verbatim in the recording. Muse Spark reads only those records; a check in code drops any statement that cites nothing or cites a record that was not fetched. Whether a pairing is reported is a count in code over the titles and abstracts read, worded as a count ("0 of 50 read"), never as novelty. Numbers inside a literature statement are quoted from their cited source, not computed here: an exception to ADR-0001 that the citation makes visible.
- **Protein cross-check.** The KPMP protein audit, computed. Descriptive only: one person per group, thresholds frozen on the healthy reference.
- **Figures** are new artifacts (SVG, PDF and a 300 dpi PNG at 180 mm) with legends written from the computed numbers; the composite figure the verifier read is never replaced.
- **Report.** What happened, why, and next steps are assembled in code from the verdict, the claims, their controls and the lab's artifacts.
- **Recording.** A recorded investigation's lab is recorded live once (`scripts/record_lab.py`); immutable replay serves it verbatim and a cached tool rerun reruns it from the stored responses. The first recording of the featured run rejected both literature tasks because the schema left `query` optional; the schema was fixed and the lab re-recorded. A second change of method (relevance order, 50 records instead of the 25 most cited) was chosen before seeing its result and recorded once; its outcome was kept.

**Uploaded sections** (`POST /api/upload/audit`): Xenium output files, uploaded or linked by https URL to a public host (no redirects, no private addresses), at most 40 MB per request (the web container has 1 GB). They are validated, labelled with the frozen GSE286184 label rules and audited by the same engine, in temporary storage deleted when the request ends. Nothing is stored and no model sees them. An audit result still needs three eligible sections.
